Instruction tuning routes moral framing, it does not create it

Decoded but unused. The direction was already in the pretrained network; tuning connected it to the part that answers.

Figure
The workEvery entry here carries the same four slots.
The question

When an instruction-tuned model starts treating a moral question differently from its base model, has post-training built a new representation, or has it wired up one that was already present?

What we found

The comparison uses a matched pretrained and instruction-tuned checkpoint from the same architecture, tokeniser and pretraining seed, so the post-training step is the only free variable. Without that control, any difference between two models can be attributed to pretraining instead.

Moral framing is already linearly decodable in the pretrained network, and it has no causal effect on that network's judgment. In the instruction-tuned checkpoint the same representation becomes aligned with, and causally usable by, the evaluative readout: the within-model framing-to-judgment alignment is 8.4 times larger than in the matched pretrained checkpoint at the same layer.

So the capability was not installed. It was already there and unused, and tuning changed how it is read out. Probes, the logit lens, residual activation patching and a within-model alignment cosine all point the same way, and per-head attribution followed by mean ablation identifies which heads actually carry it.

What would sink it

The account is falsifiable in three places. The framing should already be decodable before tuning, tuning should align it with the readout, and intervening on the aligned direction should move the judgment. Any one of those failing breaks it.
